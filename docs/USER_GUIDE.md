# SPOReplaceLink — інструкція користувача

Версія MVP (етапи 1–5), 26.10.2026.

SPOReplaceLink виправляє биті посилання в Excel-файлах (xlsx, xlsm, xlsb, xls), що лежать у бібліотеках SharePoint Online після міграції. Посилання на старі адреси (наприклад, `https://contoso.sharepoint.com/Document/Fin/…`) замінюються на нові (`https://contoso.sharepoint.com/sites/finance/Fin/…`) за правилами, які ви задаєте.

Інструкція складається з трьох частин:
- **Частина 1** — що треба знати перед початком: поняття, встановлення, запуск.
- **Частина 2** — сценарії роботи крок за кроком, від першого налаштування до бойового прогону і роботи з помилками.
- **Частина 3** — довідник: кожне поле кожного екрана (що це, навіщо, який ефект, що в результаті), статуси, звіти, команди CLI.

# Частина 1. Перед початком

## 1.1. Як це працює

Для кожного файлу застосунок робить таке:

1. Отримує список файлів бібліотеки через Microsoft Graph.
2. Завантажує файл на свою машину.
3. Знаходить у ньому посилання (гіперпосилання, зв'язки з іншими книгами, формули) і замінює старі адреси на нові за правилами.
4. Перевіряє результат: файл відкривається, кількість замін збігається, старих адрес не лишилось. Якщо перевірка не пройшла, файл не записується.
5. Записує файл назад у SharePoint, лише якщо в ньому щось змінилося і ніхто не змінив файл за цей час.

xlsx і xlsm обробляються без Excel, як архіви з XML. xls і частина xlsb обробляються через Excel, установлений на тій самій машині, — у прихованих окремих процесах.

Excel не відкриває файли з мережі, а застосунок не працює через синхронізацію OneDrive чи браузер. Уся робота — через Graph з локальною копією.

## 1.2. Основні поняття

| Поняття | Що це |
|---|---|
| **Підключення** | Застосунок, зареєстрований в Entra (Azure AD), і сертифікат, яким він входить у SharePoint. Застосунок отримує доступ лише до сайтів, які йому явно видано. |
| **Правило** | Пара «старий префікс → новий префікс». Наприклад, `https://contoso.sharepoint.com/Document` → `https://contoso.sharepoint.com/sites/finance`. Посилання, що починається зі старого префікса, отримує новий, а решта адреси (папки, ім'я файлу) лишається як є. |
| **Шаблон правил** | Іменований набір правил, який можна підключати до кількох профілів. |
| **Ціль** | Сайт + бібліотека + (необов'язково) папка, де треба виправити файли. |
| **Профіль** | Усе для прогону: правила й шаблони, цілі, фільтри, місця заміни, швидкість, повтори, підключення. |
| **Прогін** | Одне виконання профілю в одному з режимів. Має номер, стан і власну історію; продовжується після зупинки. |
| **Режим** | `inventory` — перелік, статистика і гістограма адрес; `scan` — пробна обробка без запису; `apply` — заміна і запис; `verify` — перевірка, що старих адрес не лишилося. inventory і scan обидва завантажують і розбирають кожен файл (інакше посилань не знайти), тож коштують однаково. |
| **Знімок налаштувань** | Копія профілю, шаблонів і підключень на момент створення прогону. Прогін працює лише зі знімком: зміна профілю потім на нього не впливає. |
| **Повторний прогін** | Новий прогін за вибраними файлами попереднього (наприклад, лише невдалими). Бібліотека заново не перелічується. |
| **Залишок** | Старий префікс, що лишився у файлі після заміни: місце заміни вимкнене або не підтримується, або для адреси немає правила. Завжди потрапляє у звіт. |
| **RU (resource units)** | Одиниці, в яких SharePoint рахує навантаження. Кожен застосунок має ліміт RU за хвилину і за добу. Застосунок сам стежить, щоб не перевищувати заданої частки ліміту. |

## 1.3. Гарантії безпеки

- **За замовчуванням нічого не записується.** Запис у SharePoint виконує лише режим `apply`, і він вимагає підтвердження.
- **Записуються лише змінені файли.** Файли, де нічого не змінено, не вивантажуються і не отримують нової версії.
- **Чужі зміни не перезаписуються.** Якщо файл змінили після того, як застосунок його завантажив, запис відхиляється, і файл обробляється заново з новою версією.
- **Файли, взяті на редагування** (check-out) або відкриті іншими, відкладаються й повторюються пізніше.
- **Перед записом фіксується номер версії.** Попередню версію можна повернути через журнал версій SharePoint (С12).
- **Повторний запуск по вже виправлених файлах нічого не змінює** і нічого не записує.
- **Кожен файл отримує фінальний статус**, кожна невиправлена стара адреса потрапляє у звіт.
- **Обережність щодо SharePoint.** Застосунок працює нижче ліміту навантаження. Якщо SharePoint просить почекати, пауза діє на весь застосунок. Якщо багато помилок поспіль, прогін зупиняється сам (запобіжник).

## 1.4. Вимоги і встановлення

**Машина:**
- Windows 10/11 або Windows Server з робочим столом;
- WebView2 Runtime (у Windows 10/11 уже є; інсталятор перевіряє його наявність);
- .NET окремо не потрібен: він входить у пакет;
- для xls і частини xlsb — встановлений Microsoft Excel (365, 2016+), активований для облікового запису, під яким працює застосунок;
- доступ до `login.microsoftonline.com` і `graph.microsoft.com`.

Рекомендовано окрему ВМ з автовходом облікового запису: великі прогони тривають годинами.

**Встановлення інсталятором** — `SPOReplaceLink-<версія>-x64.msi`:

- ставить застосунок у `C:\Program Files\SPOReplaceLink` (потрібні права адміністратора) і додає ярлик у меню «Пуск»;
- в одній папці лежать застосунок `SPOReplaceLink.exe`, CLI `spo-replace-link.exe`, обробник Excel і ця інструкція (`docs\`);
- новіша версія ставиться поверх старої, без видалення;
- дані (підключення, профілі, стан прогонів, журнали) зберігаються окремо, у `%LOCALAPPDATA%\SPOReplaceLink`. Оновлення і видалення застосунку їх не чіпають.

Тихе встановлення (наприклад, через Intune чи SCCM):

```bash
msiexec /i SPOReplaceLink-1.0.1-x64.msi /qn
```

**Без встановлення** — `SPOReplaceLink-<версія>-x64-portable.zip`: розпакуйте в будь-яку папку (наприклад, `C:\Tools\SPOReplaceLink`) і запускайте `SPOReplaceLink.exe`. Права адміністратора не потрібні.

**Збірка релізу з вихідного коду** (на машині розробника, потрібен .NET 10 SDK):

```bash
powershell -ExecutionPolicy Bypass -File installer\build.ps1
```

Скрипт проганяє тести, публікує застосунок і CLI разом із .NET і збирає MSI та zip в `out\release`.

**Перевірка встановлення без погляду на екран:**

```bash
SPOReplaceLink.exe --selftest C:\Temp\selftest.txt
```

У файлі має бути `RESULT ok`.

**Доступ до SharePoint** налаштовує адміністратор один раз: сертифікат, застосунок в Entra з дозволом `Sites.Selected`, видача доступу `write` на потрібні сайти. Покроково — [1.5](#15-налаштування-доступу-до-sharepoint-один-раз). Далі — сценарій [С1](#с1-перше-налаштування-доступу-до-sharepoint).

## 1.5. Налаштування доступу до SharePoint (один раз)

SPOReplaceLink входить у SharePoint як застосунок Entra (app-only), без користувача: застосунок у Entra + сертифікат. Пароля чи секрету в налаштуваннях немає — закритий ключ сертифіката лежить лише у сховищі Windows на ВМ, в Entra завантажується тільки відкрита частина.

Порядок: сертифікат на машині → застосунок у Entra → доступ до сайтів → підключення в SPOReplaceLink.

### Крок 1. Сертифікат

Сертифікат ніде купувати не треба: для входу застосунку в Entra підходить самопідписаний. Його створюють на машині, де працюватиме SPOReplaceLink, **під тим обліковим записом, під яким його запускатимуть** (інакше застосунок не побачить ключ), або у сховищі машини з доступом для цього запису (Варіант Б). Якщо в компанії є внутрішній центр сертифікації і політика вимагає його — можна видати сертифікат там; вимоги ті самі: RSA 2048+, із закритим ключем, у сховищі `My`.

**Варіант А — застосунок запускає звичайний користувач** (сховище `CurrentUser`). PowerShell під цим записом, права адміністратора не потрібні:

```powershell
$cert = New-SelfSignedCertificate -Subject "CN=spo-replace-link-1" -CertStoreLocation Cert:\CurrentUser\My -KeyAlgorithm RSA -KeyLength 2048 -KeySpec Signature -KeyExportPolicy NonExportable -HashAlgorithm SHA256 -NotAfter (Get-Date).AddYears(2)
```

**Варіант Б — сертифікат спільний для кількох облікових записів машини** (сховище `LocalMachine`). PowerShell від адміністратора, `Cert:\LocalMachine\My` замість `Cert:\CurrentUser\My`. Потім дати потрібним записам доступ до ключа: `certlm.msc` → Personal → Certificates → сертифікат → All Tasks → Manage Private Keys → додати запис з правом **Read**.

Далі в тому самому вікні PowerShell — відбиток для підключення і відкрита частина для Entra:

```powershell
$cert.Thumbprint
```

```powershell
Export-Certificate -Cert $cert -FilePath .\spo-replace-link-1.cer
```

**Де ключ, а де `.cer`.** Закритий ключ створюється разом із сертифікатом і залишається лише в тому сховищі, де виконано `New-SelfSignedCertificate`; SPOReplaceLink бере сертифікат саме звідти. `.cer` містить лише відкритий ключ і потрібен тільки для Entra (крок 2) — його можна передавати адміну поштою. **Не імпортуйте `.cer` у сховище Windows:** так з'являється копія сертифіката без закритого ключа, і застосунок покаже її як «(без закритого ключа)».

`NonExportable` означає, що закритий ключ не можна вивантажити (ні в `.pfx`, ні інакше): сертифікат не переноситься на іншу ВМ чи в інший обліковий запис. Для іншого запису на цій машині — Варіант Б (`LocalMachine` і право **Read** на ключ), для нової ВМ — новий сертифікат, доданий до застосунку в Entra поруч зі старим. Знайти відбиток і перевірити ключ пізніше: `Get-ChildItem Cert:\CurrentUser\My | Format-List Subject, Thumbprint, HasPrivateKey` (або `LocalMachine\My`).

У списку сертифікатів підключення ([3.1](#31-підключення)) позначено: «(без закритого ключа)» — у цьому сховищі лише відкрита частина; «(немає доступу до ключа)» — ключ є, але обліковому запису, під яким працює застосунок, не надано право **Read** (Варіант Б).

Сертифікат діє 2 роки. Перед завершенням створити новий, додати його до застосунку поруч зі старим, змінити сертифікат у підключенні, потім видалити старий. Застосунок відмовляється від простроченого сертифіката з помилкою `failed:auth`.

### Крок 2. Застосунок у Entra

Потрібен адмін Entra (Application Administrator або Global Administrator).

1. [Entra admin center](https://entra.microsoft.com) → **App registrations** → **New registration**: назва, наприклад `spo-replace-link-1`; **Accounts in this organizational directory only**; Redirect URI не потрібен.
2. На сторінці **Overview** записати **Application (client) ID** (поле **Client ID** підключення) і **Directory (tenant) ID** (поле **Тенант**; або домен `…onmicrosoft.com`).
3. **Certificates & secrets** → **Certificates** → **Upload certificate** → файл `.cer` з кроку 1. Відбиток, показаний в Entra, має збігатися з `$cert.Thumbprint`.
4. **API permissions** → **Add a permission** → **Microsoft Graph** → **Application permissions** → **Sites.Selected** → **Add**. Дозвіл `User.Read` (Delegated), доданий за замовчуванням, можна видалити.
5. **Grant admin consent for …** — статус має стати зеленим «Granted».

Sites.Selected сам по собі не дає доступу до жодного сайту — лише до тих, які видано явно на наступному кроці.

### Крок 3. Доступ до сайтів

Після кроку 2 застосунок має дозвіл `Sites.Selected`, але **ще не має доступу до жодного сайту**: доступ видають окремо на кожен сайт. Доки цього не зроблено, перевірка підключення отримує токен, але на ціль відповідає `403`.

**Що видати.** Роль `write` на кожну **колекцію сайтів**, де лежать цільові бібліотеки (адреса виду `https://contoso.sharepoint.com/sites/Fin`). Цього достатньо для всіх режимів: читання файлів і версій, запис виправлених файлів. Роль діє на всі бібліотеки й підсайти колекції; дозволи бібліотек вона не змінює (успадкування не розривається).

| Роль | Чи підходить |
|---|---|
| `read` | Лише інвентаризація і сканування; застосування змін завершиться `403`. |
| `write` | **Потрібна.** |
| `owner`, `fullcontrol` | Зайві: дають керування сайтом і правами. |

**Хто видає.** Адмін SharePoint або Global Administrator — обліковий запис, якому можна погодити дозвіл `Sites.FullControl.All` (саме він потрібен, щоб видавати доступ до сайтів). Самому застосунку `spo-replace-link-1` цей дозвіл **не додають**, і `Sites.ReadWrite.All` теж: з ними обмеження за сайтами перестає діяти.

Знадобляться **Client ID** застосунку з кроку 2 і адреси сайтів. Нижче три рівноцінні способи — оберіть той, що зручніший адміну.

#### Спосіб 1. Graph Explorer (у браузері, нічого не встановлювати)

1. Відкрити [Graph Explorer](https://developer.microsoft.com/graph/graph-explorer) і увійти обліковим записом адміна.
2. **Modify permissions** (вкладка над запитом) → знайти `Sites.FullControl.All` → **Consent**. Якщо кнопка недоступна — потрібна згода Global Administrator.
3. Отримати ідентифікатор сайту: метод **GET**, адреса нижче → **Run query** → скопіювати поле `id` з відповіді (вигляду `contoso.sharepoint.com,5a58…,9f2e…`).

```http
GET https://graph.microsoft.com/v1.0/sites/contoso.sharepoint.com:/sites/Fin
```

4. Видати доступ: метод **POST**, адреса з цим `id`, у **Request body** — JSON нижче (підставити Client ID) → **Run query**. Відповідь `201 Created`.

```http
POST https://graph.microsoft.com/v1.0/sites/{id сайту}/permissions
Content-Type: application/json

{
  "roles": ["write"],
  "grantedToIdentities": [{ "application": { "id": "<Client ID застосунку>", "displayName": "spo-replace-link-1" } }]
}
```

5. Перевірити: **GET** `https://graph.microsoft.com/v1.0/sites/{id сайту}/permissions` — у списку є запис зі `spo-replace-link-1` і роллю `write`.

Повторити кроки 3–5 для кожного сайту.

#### Спосіб 2. PnP.PowerShell (зручно для багатьох сайтів)

Потрібні PowerShell 7.4+ і модуль `Install-Module PnP.PowerShell -Scope CurrentUser`. Для входу PnP потрібен власний застосунок у Entra — його реєструють один раз (Global Administrator погоджує дозволи), і далі використовують його Client ID:

```powershell
Register-PnPEntraIDAppForInteractiveLogin -ApplicationName "PnP PowerShell" -Tenant contoso.onmicrosoft.com
```

Видати доступ (вхід — до будь-якого сайту тенанта, сайт для дозволу задає `-Site`):

```powershell
Connect-PnPOnline -Url https://contoso.sharepoint.com -Interactive -ClientId <Client ID застосунку PnP>
```

```powershell
Grant-PnPEntraIDAppSitePermission -AppId <Client ID spo-replace-link-1> -DisplayName spo-replace-link-1 -Site https://contoso.sharepoint.com/sites/Fin -Permissions Write
```

Кілька сайтів одразу:

```powershell
"https://contoso.sharepoint.com/sites/Fin", "https://contoso.sharepoint.com/sites/finance" | ForEach-Object { Grant-PnPEntraIDAppSitePermission -AppId <Client ID spo-replace-link-1> -DisplayName spo-replace-link-1 -Site $_ -Permissions Write }
```

Перевірити: `Get-PnPEntraIDAppSitePermission -Site https://contoso.sharepoint.com/sites/Fin`. Старі версії PnP мають ті самі команди з назвами `…PnPAzureADAppSitePermission`.

#### Спосіб 3. Microsoft Graph PowerShell

```powershell
Connect-MgGraph -Scopes Sites.FullControl.All
```

```powershell
$site = Get-MgSite -SiteId "contoso.sharepoint.com:/sites/Fin"
New-MgSitePermission -SiteId $site.Id -BodyParameter @{ roles = @("write"); grantedToIdentities = @(@{ application = @{ id = "<Client ID spo-replace-link-1>"; displayName = "spo-replace-link-1" } }) }
```

Перевірити: `Get-MgSitePermission -SiteId $site.Id`.

#### Після видачі

- **Перевірити в SPOReplaceLink:** **Підключення → Перевірити підключення** з профілем, що містить цей сайт. Кожна ціль має бути зеленою. Якщо доступ щойно видано, а перевірка ще дає `403` — повторіть за кілька хвилин.
- **Новий сайт у профілі** — спершу видати на нього доступ так само, інакше прогін для цієї цілі завершиться помилкою доступу.
- **Пошук сайтів** у редакторі профілю може не знаходити сайти, на які не видано доступ, — вводьте адресу сайту повністю.
- **Відкликати доступ** після завершення робіт: у Graph — `DELETE https://graph.microsoft.com/v1.0/sites/{id сайту}/permissions/{id дозволу}` (`id дозволу` — з відповіді GET `…/permissions`); у PnP — `Revoke-PnPEntraIDAppSitePermission -PermissionId <id> -Site …`; у Graph PowerShell — `Remove-MgSitePermission`. Повністю вимкнути застосунок для всіх сайтів можна, відкликавши згоду на `Sites.Selected` у Entra (крок 2).

### Крок 4. Підключення в SPOReplaceLink

У вікні застосунку — сценарій [С1](#с1-перше-налаштування-доступу-до-sharepoint): **Підключення → Створити**, тенант, Client ID, сертифікат зі сховища, **Перевірити підключення**. Для кількох застосунків у пулі — по підключенню на кожен, з різними назвами.

З командного рядка — імпорт JSON (`tenantId`, `clientId`, `certificateThumbprint`, `certificateStore` — `CurrentUser` або `LocalMachine`, як у кроці 1, і `licenses`) і перевірка: `test` отримує токен і пробує прочитати кожну ціль профілю.

```bash
spo-replace-link connections import connection.json
```

```bash
spo-replace-link connections test spo-replace-link-1 --profile finance
```

**Якщо перевірка не проходить:**
- «Сертифікат … не знайдено у сховищі» — застосунок запущено під іншим записом, ніж той, під яким створено сертифікат, або вибрано не те сховище;
- «без закритого ключа» — у вибраному сховищі лише імпортований `.cer`; виберіть сховище, де сертифікат створено, або створіть новий (`.cer` у сховище не імпортують);
- «Немає доступу до закритого ключа» — у варіанті Б обліковому запису застосунку не видано Read на ключ;
- `AADSTS700027` / `AADSTS700016` — сертифікат не завантажено в застосунок або хибний Client ID / тенант;
- токен є, але `403` на ціль — не дано згоду адміна на Sites.Selected (крок 2) або не видано `write` на цей сайт (крок 3).

## 1.6. Запуск застосунку

```bash
SPOReplaceLink.exe --data D:\SPOReplaceLink
```

| Параметр | Що це | Навіщо і ефект | За замовчуванням |
|---|---|---|---|
| `--data <папка>` | Папка даних: база стану, журнали, тимчасові файли. | Усі налаштування і прогони лежать тут. Інша папка — окремий незалежний набір даних. **Рекомендовано на диску D:** (не на тому, де лежать локальні файли, на які посилаються Excel-книги, — див. [С10](#с10-файли-xls-і-xlsb-excel)). | `%LOCALAPPDATA%\SPOReplaceLink` |
| `--urls <адреса>` | Адреса локального API для CLI. | Зазвичай не потрібна. Якщо порт зайнятий (наприклад, застосунок уже запустив інший користувач цієї машини), API бере вільний порт і записує адресу в `api.json` у папці даних — CLI того ж користувача знайде її сам. Явний `--urls` потрібен лише для фіксованої адреси; якщо вона зайнята, застосунок попередить і назве фактичну. | `http://localhost:5080` |
| `--selftest <файл>` | Самоперевірка: запуск, відкриття розділів, запис результату, вихід. | Перевірка встановлення і оновлення. | — |

На одну папку даних працює один екземпляр: повторний запуск відкриває вже запущене вікно.

**Кілька користувачів на одній машині.** Кожен користувач запускає застосунок під своїм обліковим записом: у нього своя папка даних (`%LOCALAPPDATA%\SPOReplaceLink`), свої налаштування, прогони і сертифікат. Перший екземпляр слухає `localhost:5080`, наступні — вільні порти; CLI кожного користувача сам знаходить свій екземпляр через `api.json`. API приймає лише запити з ключем свого екземпляра (він теж в `api.json`), тож інший користувач машини не може керувати чужими прогонами. Не кладіть папку даних (`--data`) у спільну для кількох записів папку: з неї інші зможуть прочитати ключ.

**Автозапуск на ВМ.** Щоб прогін продовжувався після перезавантаження, увімкніть автовхід облікового запису і додайте в Планувальник завдань завдання «При вході в систему» з командою `SPOReplaceLink.exe --data D:\SPOReplaceLink`. Прогін, перерваний збоєм або примусовим завершенням процесу, застосунок продовжує сам. Прогін, зупинений звичайним виходом із застосунку, має стан «зупинено» і продовжується кнопкою **Продовжити прогін** (або `spo-replace-link start <прогін>`). Перед плановим перезавантаженням ВМ зупиніть прогін або перевірте після перезавантаження, що він продовжився.

## 1.7. Вікно застосунку

Ліворуч — меню:
- **Дашборд** — поточний прогін (або останній, якщо зараз нічого не виконується);
- **Прогони** — список прогонів і кнопка «Новий прогін»;
- **Налаштування:** **Профілі**, **Шаблони правил**, **Підключення**.
- **Довідка** — ця інструкція всередині застосунку: розділи деревом, пошук, кнопки «попередній / наступний».

Біля заголовків екранів і на кожній вкладці профілю є кнопка **?** («Що означають ці поля», «Довідка»). Вона відкриває у вікні розділ інструкції саме про ці поля; **Відкрити в довідці** — той самий розділ на сторінці довідки. Кнопка **?** у верхньому правому куті відкриває довідку з початку.

У кожному списку налаштувань (профілі, шаблони, підключення) є:
- **Створити**, **Імпорт JSON**;
- для кожного рядка — експорт JSON, перейменування (посилання в профілях оновлюються), клонування і видалення (застосунок попередить, які профілі використовують шаблон або підключення).

Закриття вікна під час прогону — див. [С11](#с11-пауза-зупинка-закриття-вікна-перезавантаження).

# Частина 2. Сценарії

## С1. Перше налаштування доступу до SharePoint

**Мета:** застосунок отримує токен і бачить потрібні бібліотеки.

**Що потрібно від адміністратора:** Tenant ID, Client ID застосунку, сертифікат у сховищі Windows на цій машині (під вашим обліковим записом) і доступ `write` до сайтів. Як це налаштувати — [1.5](#15-налаштування-доступу-до-sharepoint-один-раз).

1. **Підключення → Створити.**
2. Заповніть:
   - **Назва** — наприклад, `spo-replace-link-1`;
   - **Тенант** — домен `…onmicrosoft.com` або GUID;
   - **Client ID**.
3. **Автентифікація** — «Сертифікат». У списку **Сертифікат зі сховища Windows** виберіть свій сертифікат: відбиток і сховище заповняться самі.
4. **Ліцензій у тенанті** — виберіть діапазон. Від нього залежать ліміти навантаження (таблиця праворуч).
5. **Зберегти.**
6. **Перевірити підключення:** спершу без профілю — має з'явитися «токен: Токен отримано». Коли буде профіль ([С3](#с3-профіль-для-бібліотеки)), виберіть його й перевірте ще раз — для кожної цілі має бути «Доступ є».

**Результат:** підключення збережене і перевірене. Якщо перевірка не проходить — [3.14](#314-якщо-щось-пішло-не-так).

## С2. Правила заміни (шаблон)

**Мета:** набір правил «старе розташування → нове», який можна перевірити до будь-якого прогону.

1. **Шаблони правил → Створити**, назва (наприклад, `finance`), опис.
2. Заповніть правила одним із двох способів:
   - **вручну** — **Додати правило**: «Старий префікс» і «Новий префікс»;
   - **імпортом** — **Імпорт правил**: таблиця відповідності CSV/XLSX з двома стовпцями (старий, новий) або текст зі списку ReplaceMagic.
3. Стежте за повідомленнями під рядками: дублікати, конфлікти, цикли (A→B і B→A) і правила, результат яких інше правило змінило б при повторному прогоні. Помилки треба виправити, попередження — переглянути.
4. **Перевірити посилання:** вставте реальне старе посилання з файлу. Застосунок покаже:
   - нормалізовану адресу;
   - які правила збіглися (✔ — те, що спрацює);
   - результат;
   - чи не змінило б його повторне застосування.

   Для відносних посилань (`../Analytics/a.xlsx`) заповніть «Стара папка документа».
5. **Зберегти.** **CSV** — експорт правил для погодження з власниками даних.

**Як працюють правила:**
- **порядок не має значення** — спрацьовує правило з найдовшим старим префіксом;
- **лише на межі папки** — `/Document` не зачепить `/Documents` чи `/MyDocument`;
- **регістр і кодування не мають значення** — `%20` і пробіл, кирилиця закодована чи ні, `\` і `/`;
- **замінюється лише префікс** — хвіст адреси (папки, файл, `#Аркуш!A1`) копіюється без змін, у тому ж стилі кодування, що й в оригіналі;
- **префікс може бути** повною адресою (`https://…`), мережевим шляхом (`\\server\share`), локальним шляхом (`C:\Users\…`) або шляхом від кореня сайту (`/Document/…`) — для останнього в профілі потрібен `baseHost`.

**Результат:** шаблон, який можна підключити до профілю.

## С3. Профіль для бібліотеки

**Мета:** усе, що потрібно для прогону по конкретній бібліотеці.

1. **Профілі → Створити**, назва (наприклад, `finance-pilot`).
2. **Загальне і правила:**
   - `baseHost` — `https://contoso.sharepoint.com`;
   - виберіть шаблон(и);
   - за потреби додайте власні правила профілю. Вони перевіряються разом із правилами шаблонів.
3. **Підключення:** виберіть підключення з С1.
4. **Цілі → Додати ціль:**
   - вставте адресу сайту → **Відкрити**;
   - виберіть **Бібліотеку**;
   - за потреби перейдіть у папку → **Взяти цю папку**;
   - заповніть **Стару адресу** цієї бібліотеки (де вона була до міграції), якщо у файлах є відносні посилання.
5. **Фільтри:** залиште всі розширення. Виключіть архіви чи службові папки масками (наприклад, `**/Архів/**`).
6. **Місця заміни:** залиште все ввімкненим, якщо немає причини інакше.
7. **Продуктивність:** для пілоту — пресет **Обережно**; для бойового прогону — **Неробочий час**.
8. **Зберегти.** Застосунок перевірить профіль і позначить помилки на вкладках і біля полів. Профіль з помилками зберігається, але не запускається.
9. Поверніться в **Підключення → Перевірити** з цим профілем.

**Результат:** профіль, готовий до запуску.

## С4. Інвентаризація і доповнення правил

**Мета:** побачити, які адреси реально є у файлах, і чи всі вони покриті правилами. Нічого не записується, але кожен файл завантажується і розбирається — за часом і навантаженням це як scan. Результат inventory одразу показує й те, що буде замінено (статуси `planned`), тож окремий scan потрібен лише після зміни правил.

1. **Прогони → Новий прогін**, профіль, режим **inventory**, **Запустити**.
2. Після завершення: **Звіти → Префікси — XLSX**. Застосунок спитає глибину — скільки рівнів папок під сайтом, сервером чи диском лишати в префіксі (1–10, за замовчуванням 2; у CLI — `export … --prefix-depth N`). Кожен рядок — початок адреси до цієї глибини і скільки посилань і файлів його містять. Якщо різні папки однієї бібліотеки переїжджають у різні місця, збільште глибину. Стовпці:
   - `replaced` — покрито правилами;
   - `no_rule` — правила немає;
   - `unresolved` — відносне посилання, яке не вдалося розв'язати.
3. Пройдіться по рядках з `no_rule` > 0:
   - **стара адреса, яку треба виправити** — додайте правило в шаблон (С2);
   - **адреса, яку чіпати не треба** (зовнішній сайт, нова адреса) — нічого не робіть;
   - **локальні шляхи `C:\Users\…`, старі сервери** — вирішіть з власниками даних: чи є, куди їх вести.
4. Рядки з `unresolved` > 0 означають, що для бібліотеки не задано **Стару адресу** (ціль) або її не вдається вивести з правил. Заповніть її.

**Результат:** правила покривають усе, що треба виправити. Кількість файлів у профілі тепер видно на вкладках «Цілі» і «Фільтри» (за останнім прогоном цього профілю, який перелічував бібліотеку).

## С5. Пробний прогін (scan) і перевірка звіту

**Мета:** побачити, що саме буде замінено, до будь-якого запису.

1. **Новий прогін**, режим **scan**.
2. На дашборді:
   - **Змінено** (тут — «буде змінено»);
   - **Замін посилань** з розбивкою за місцями;
   - **З залишками**;
   - **Помилки**.
3. Перегляньте звіти:
   - **Посилання** — кожна заміна: файл, частина файлу, тип, старе й нове значення, номер правила;
   - **Вибірка для перевірки** — 30 випадкових файлів, які буде змінено, з посиланням на файл і прикладами замін. Пройдіться по ній вручну: чи веде кожна нова адреса туди, куди треба (стовпці `checked`, `comment` — для ваших позначок);
   - **Залишки** — що лишиться невиправленим ([С9](#с9-залишки-старих-адрес));
   - **Потребують уваги** — файли з помилками і що з ними робити.
4. Якщо щось не так, виправте правила і запустіть scan ще раз. Нічого не записано, тож повторювати можна скільки завгодно.

**Результат:** ви знаєте, що зробить apply, і погодили це.

## С6. Пілот на одній бібліотеці

**Мета:** перевірити інструмент на реальних даних і реальному SharePoint на одній бібліотеці, перш ніж запускати на всіх. Пілот — обов'язковий крок перед бойовим прогоном.

**Підготовка:**
1. Виберіть одну бібліотеку з різними файлами (xlsx, xlsm, xls, xlsb, файли зі зв'язками між книгами). Краще з власником, який погодиться перевірити файли.
2. Переконайтеся, що в бібліотеці увімкнено **журнал версій** (Параметри бібліотеки → Параметри версій) і ліміт версій не дуже малий: кожен записаний файл отримує одну нову версію.
3. Профіль: одна ціль, пресет **Обережно**. Попросіть власників ключових файлів не редагувати їх під час прогону, або запускайте в неробочий час.

**Хід пілоту:**
1. **inventory** → доповніть правила ([С4](#с4-інвентаризація-і-доповнення-правил)).
2. **scan** (якщо правила змінилися; інакше — звіти того ж inventory) → ручна перевірка вибірки ([С5](#с5-пробний-прогін-scan-і-перевірка-звіту)).
3. **apply.** Діалог покаже кількість файлів; поставте прапорець підтвердження. Під час прогону стежте за панеллю **Навантаження на SharePoint**: відповіді 429/503 і паузи мають бути поодинокими або відсутніми.
4. Після завершення — **Перевірити (verify)** на картці прогону. Verify заново завантажує всі записані файли і шукає старі адреси ([як це працює](#кнопка-перевірити-verify)). Очікуваний результат: 0 файлів «Ще треба змінити», 0 залишків (крім узгоджених).
5. **Звіти → Звіт пілоту — TXT** для прогону apply. Він містить:
   - скільки файлів записано, за форматами;
   - **RU на файл** порівняно з планом (~2 для файлу без змін, ~4 для зміненого) і кількість 429/503;
   - швидкість за час активної обробки (без очікування вікон, пауз і перерв між запусками), секунди на файл, межу швидкості за бюджетом RU (з урахуванням вікон і добового ліміту) і **прогноз часу на 10 000 файлів** та на профіль. Для інших бібліотек: кількість їхніх файлів × секунди на файл;
   - **чи віддає SharePoint номер версії до запису.** Якщо 0 з N, відкат за версією і кнопка «Зберегти версію до зміни» не працюватимуть — передайте звіт розробнику;
   - **чи змінює SharePoint файл під час збереження** (дописує властивості колонок бібліотеки) — за розміром у відповіді на запис. На коректність це не впливає, але знати треба;
   - скільки спроб закінчилися конфліктом (412) і блокуванням (423, check-out), включно з тими, після яких файл зрештою записався;
   - помилки, згруповані з рекомендаціями;
   - Excel: операції, зависання, падіння.
6. **Перевірка користувачами.** Дайте власникам список ключових файлів (звіт «Вибірка для перевірки» або власний). Попросіть кожного відкрити файл у браузері та в Excel і перевірити:
   - чи немає попередження про відновлення файлу;
   - гіперпосилання відкриваються;
   - **Дані → Змінити зв'язки** показує нові адреси, а **Оновити значення** бере дані з нового джерела;
   - формули з `HYPERLINK` ведуть на нові адреси;
   - для книг з макросами — макроси працюють.

**Критерій успіху пілоту:**
- verify: 0 «Ще треба змінити», залишки лише узгоджені;
- користувачі підтвердили ключові файли;
- 429 немає або вони поодинокі, без блокування;
- немає `failed:validation` і `failed:internal` (або їх розібрано з розробником);
- RU на файл і прогноз часу прийнятні для повного обсягу.

**Якщо щось не так:** зберіть звіти (`export`, [3.11](#311-командний-рядок-cli)) і журнал (`logs\host-*.jsonl` у папці даних) і передайте розробнику. Окремий файл можна повернути до попередньої версії ([С12](#с12-повернути-попередню-версію-файлу)).

## С7. Бойовий прогін

**Мета:** виправити всі бібліотеки з мінімальним впливом на користувачів.

1. Для кожної групи бібліотек — профіль. Можна один профіль з кількома цілями, але партії (по одній чи кілька бібліотек) легше контролювати.
2. Продуктивність: пресет **Неробочий час**. Він працює лише у вікнах пн–пт 20:00–07:00 і в усі вихідні, з бюджетом 80%. Поза вікнами прогін сам стає на паузу і продовжується, коли настає наступне вікно.
3. **apply** → **verify** → перегляд помилок → повтори ([С8](#с8-помилки-і-повтори)).
4. Після останньої партії — фінальний **verify** за профілем (Новий прогін → verify), експорт звітів і копія папки даних в архів: там історія всіх змін і номери версій до запису.

**Пул застосунків** (кілька підключень в одному прогоні) вмикайте лише якщо одного застосунку справді не вистачає за часом. Microsoft не рекомендує кілька застосунків для однієї задачі: вони ділять один тенантний бюджет з користувачами і з іншими застосунками (бекап, міграція). Тому сумарне навантаження обмежене стелею (за замовчуванням 50% тенантного бюджету).

## С8. Помилки і повтори

**Мета:** кожен файл має фінальний статус, а невдалі файли повторюються вибірково, без нового проходу бібліотеки.

**Що застосунок робить сам:**
- **збої мережі і SharePoint** (5xx, 429, обрив) — до 6 спроб запиту, потім файл береться заново: усього до 3 спроб файлу з паузами 1 і 5 хв (список пауз — 1, 5, 15: третє значення діє, якщо збільшити кількість спроб);
- **файл змінили під час обробки** (412) — обробляється заново зі свіжою версією, у межах тих самих 3 спроб файлу; далі `failed:conflict`;
- **файл відкритий або взятий на check-out** (423) — відкладається; повторюється хвилями кожні 10 хв протягом 2 год;
- **Excel завис або впав** — ще одна спроба в новому процесі Excel.

**Що робите ви — після завершення прогону:**
1. **Картка прогону → Помилки й увага.** Помилки згруповано за статусом і повідомленням, біля кожної групи — що робити.
2. Для групи:
   - ☰ — показати файли групи;
   - ↻ — повторити групу (новий прогін за цими файлами);
   - ⊘ — ігнорувати з коментарем.
3. Або **Повторити…** на картці прогону — повтор за фільтром (статуси, класи помилок, розширення, маска шляху). Або на вкладці **Файли** — вибрати рядки → **Повторити вибрані**.
4. Кожен повтор — новий прогін з посиланням на батьківський. Кожен файл у ньому завантажується заново.

**Типові дії за класами** (детально — [3.9](#39-класи-помилок-і-що-робити)):
- **тимчасова, конфлікт** — повторити;
- **заблоковано** — попросити власника закрити файл або повернути check-out, повторити пізніше;
- **доступ** — перевірити права застосунку на сайт;
- **файл** — переглянути вручну (пошкоджений, з паролем, не Excel) або ігнорувати;
- **самоперевірка, внутрішня** — передати розробнику.

**Запобіжник.** Прогін зупиняється сам (статус «перервано» з причиною на дашборді), якщо:
- 10 помилок доступу поспіль;
- серед останніх 50 результатів обробки понад половина — тимчасові, доступу чи внутрішні помилки. Рахуються й проміжні невдалі спроби (файл, що тричі мав тимчасову помилку, дає три), тож при масових збоях запобіжник спрацьовує швидше. Блокування, конфлікти, помилки Excel, файлу і самоперевірки запобіжник не рахує;
- SharePoint 15 хв відповідає лише 503 (можливе блокування застосунку).

Усуньте причину і натисніть **Продовжити прогін**. Якщо це блокування, не продовжуйте одразу: повторні спроби лише подовжують блокування.

## С9. Залишки старих адрес

Статус `…:residual` означає, що заміни виконано, але у файлі лишилися старі префікси. Причини:
- для цієї адреси немає правила;
- місце заміни вимкнено в профілі;
- місце не підтримується (pivot-кеші, підключення до даних, Power Query, текст клітинок, VBA).

1. **Звіти → Залишки:** файл, частина файлу (`xl/pivotCache/…`, `xl/connections.xml`, `xl/vbaProject.bin` тощо), знайдений збіг і контекст.
2. Якщо бракує правила — доповніть шаблон.
3. **Повторити…** зі статусами `done:residual`, `unchanged:residual` або `planned:residual` і прапорцем **Взяти поточну версію профілю** — повтор піде з новими правилами. CLI: `spo-replace-link retry <прогін> --status done:residual unchanged:residual --current-profile`.
4. Залишки в непідтримуваних місцях лишаються у звіті: їх виправляють вручну або погоджують як допустимі.

## С10. Файли xls і xlsb (Excel)

- **xlsx, xlsm** і посилання **xlsb** у зв'язках обробляються без Excel.
- **xls**, а також **xlsb**, у бінарних записах яких лишилися старі адреси (наприклад, формула `HYPERLINK`), обробляються через Excel:
  1. Excel зберігає копію як xlsm;
  2. посилання в копії замінює той самий рушій, що й для xlsx;
  3. Excel зберігає результат у вихідному форматі;
  4. Excel відкриває результат ще раз і перевіряє, що старих адрес не лишилось.
- Excel працює прихованим, без діалогів, без оновлення зв'язків, з вимкненими макросами, лише з локальною копією. Кешовані значення зв'язків зберігаються.
- **Кількість процесів Excel і таймаут** — профіль → Продуктивність. Якщо Excel не відповідає довше за таймаут, процес завершується примусово, і файл отримує ще одну спробу. Якщо й вона невдала — `failed:excel`.
- **Без Excel** (не встановлено або 0 процесів) такі файли отримують `needs_excel`. Обробіть їх пізніше повторним прогоном зі статусом `needs_excel` на машині з Excel.
- **Файли з паролем** (на відкриття або на зміну) — `skipped:encrypted`, Excel для них не запускається. Пароль у xls застосунок помічає сам, ще до Excel, за вмістом файлу. Деталі й повтор — [С10а](#с10а-файли-з-паролем).
- **Діалоги Excel.** Якщо Excel усе ж щось запитує (деякі версії показують запит пароля навіть тоді, коли він не потрібен), обробник одразу закриває вікно як «Скасувати». Якщо вікно не закривається за 5 с, цей Excel завершується примусово. Файл отримує `skipped:encrypted` (питали пароль) або `failed:file` (інше питання), а наступний файл бере новий процес Excel. На дашборді лічильник «закритих діалогів».
- Після прогону процесів `EXCEL.EXE` від застосунку не лишається. Ваш власний Excel застосунок не чіпає.
- **Недавні файли провідника.** Деякі версії Excel записують кожну відкриту книгу в «Недавні елементи» Windows, і в провіднику («Швидкий доступ → Нещодавні файли») з'являються тимчасові копії `book.xls`, `book-out.xls`. Застосунок видаляє ярлики, що ведуть у його тимчасову папку, після кожного файлу, в кінці прогону й на початку наступного. Ваші власні недавні файли й налаштування Windows не змінюються. Список переходів Excel на панелі завдань застосунок не чистить.
- **Посилання на локальний диск** в xls/xlsb. Якщо файл посилається на інший файл на тому ж диску, де лежить папка даних застосунку (за замовчуванням C:), Excel зберіг би таке посилання без літери диска. Тому такий файл не записується і отримує `failed:validation` з поясненням. **Розв'язання:** папка даних на іншому диску (`--data D:\SPOReplaceLink`) і повтор.

## С10а. Файли з паролем

Застосунок не знає паролів і не підбирає їх. Файл із паролем пропускається, а прогін іде далі.

1. **Що відбувається.** Файл отримує `skipped:encrypted` з поясненням: пароль на відкриття, пароль на зміну або «Excel запитав …». Запис іде в журнал прогону (вкладка **Помилки й увага**, сторінка файлу → спроби) і в журнал застосунку. Сам файл у SharePoint не змінюється.
2. **Де їх знайти.** На вкладці **Помилки й увага** вони стоять окремою групою. На вкладці **Файли** — фільтр за статусом `skipped:encrypted`. Список для власників можна вивантажити звітом.
3. **Що зробити.** Власник файлу знімає пароль (Файл → Відомості → Захистити книгу → Зашифрувати паролем, поле порожнє; для пароля на зміну — Зберегти як → Сервіс → Загальні параметри) або сам виправляє посилання.
4. **Повторний прохід.** **Повторити…** зі статусом `skipped:encrypted` (або кнопка повтору біля групи на вкладці **Помилки й увага**). CLI: `spo-replace-link retry <прогін> --status skipped:encrypted`. Файли, з яких пароль ще не знято, знову отримають `skipped:encrypted` і чекатимуть наступного повтору.
5. Файл, який залишиться з паролем, можна **ігнорувати** з коментарем, щоб він не брався в наступні повтори.

## С11. Пауза, зупинка, закриття вікна, перезавантаження

| Дія | Що відбувається | Як продовжити |
|---|---|---|
| **Пауза** | Нові файли не беруться, поточні завершуються. Пауза діє, поки застосунок відкритий: після перезапуску прогін продовжиться сам. | **Продовжити** |
| **Зупинити** | Файли, що вже записуються в SharePoint, дописуються до кінця; решта поточних файлів переривається і повертається в чергу (нічого не записано), разом з іншими. Статус «зупинено». | **Продовжити прогін** на картці прогону |
| **Закрити вікно під час прогону** | Застосунок питає: згорнути в трей (прогін триває) або зупинити й вийти. | Подвійний клік по іконці біля годинника; після виходу — запустити застосунок і **Продовжити прогін** |
| **Збій або примусове завершення процесу** | Прогін перерваний посередині. | Після запуску застосунок продовжує сам з того самого місця. Файли, що були в обробці, обробляються заново; уже записане повторно не записується. |
| **Звичайний вихід, зокрема під час перезавантаження Windows** | Як «Зупинити» (якщо застосунок встиг завершитися коректно). | **Продовжити прогін** після запуску |
| **Поза вікнами роботи** (пресет «Неробочий час») | Прогін чекає наступного вікна. | Сам |
| **Вичерпано добовий бюджет RU** | Пауза до відновлення бюджету, файли не отримують помилок. | Сам |
| **Видалити…** (картка завершеного або зупиненого прогону) | Після підтвердження прогін зникає з усіма результатами: перелік файлів, статуси, спроби, посилання, метрики. Він більше не показується в списку, звітах і в оцінці обсягу нового прогону («За переліком прогону N…»). У SharePoint нічого не змінюється. Повтори, створені з нього, лишаються, лише без посилання на батьківський. Прогін, що виконується або на паузі, видалити не можна — спершу **Зупинити**. Якщо прогін записував файли (apply), разом з ним зникає журнал змін і версії до запису для відкату ([С12](#с12-повернути-попередню-версію-файлу)): вивантажте звіти перед видаленням. CLI: `delete-run <прогін> [--yes]`. | — |

Меню іконки в треї: **Відкрити**, **Папка даних** (відкрити в провіднику), **Вийти**.

## С12. Повернути попередню версію файлу

1. Знайдіть файл: картка прогону → **Файли** → пошук за шляхом → клік по рядку.
2. У картці файлу:
   - **Відкрити в SharePoint** — файл у браузері;
   - **Зберегти версію до зміни (N)** — завантажити копію версії, яка була до запису (щоб порівняти).
3. Щоб повернути, у SharePoint: **Журнал версій** файлу → версія з номером «Версія до запису» з картки → **Відновити**.

Масовий відкат (`rollback`) з'явиться в наступних версіях. Номери версій до запису є у звіті **Файли** (`version_before`).

## С13. Запуск за розкладом з командного рядка

Застосунок має бути відкритий (можна згорнутим у трей): CLI працює через нього.

```bash
spo-replace-link apply finance --wait --yes
```

```bash
spo-replace-link export 12 -o D:\Reports\run-12
```

Для Планувальника завдань використовуйте коди виходу:
- `0` — усе добре;
- `1` — є файли, що потребують уваги;
- `2` — помилка налаштувань або застосунок не запущений;
- `3` — прогін зупинено.

Довідка — [3.11](#311-командний-рядок-cli).

## С14. Обробка локальної папки без SharePoint

Для перевірки правил на копіях файлів або для ручних випадків. Профіль — JSON-файл без шаблонів (правила в `rules`).

```bash
spo-replace-link local D:\Copies\Fin -c finance.profile.json --base-url https://contoso.sharepoint.com/Document/Fin --out D:\Fixed\Fin --write
```

- **Без `--write`** — лише звіти (dry-run).
- **З `--write --out`** — змінені копії пишуться в іншу папку, вихідні файли не змінюються.
- **`--base-url`** — стара адреса папки, від якої розв'язуються відносні посилання.
- **`--excel N`** — кількість процесів Excel.
- **`--temp`** — тимчасова папка (на іншому диску, якщо файли посилаються на локальні шляхи).

## С15. Перенесення налаштувань на іншу машину

1. На старій машині: експорт JSON кожного підключення, шаблону і профілю (кнопка ⤓ у списку або `spo-replace-link profiles get finance -o finance.json`).
2. На новій: створити свій сертифікат (закритий ключ не переноситься), додати його до застосунку в Entra.
3. Імпорт JSON у тому ж порядку: підключення → шаблони → профілі. У підключенні — новий відбиток.
4. Перевірити підключення з профілем.

Історія прогонів лежить у `state.db` папки даних. Для архіву скопіюйте всю папку даних, коли застосунок закритий.

| Вікна роботи (`performance.windows`) | Список: **Дні** (Mon…Sun; порожньо — щодня), **З** і **До** (ГГ:ХХ, `24:00` — кінець доби; вікно може переходити через північ і належить дню початку), **Бюджет, %**. | Свій бюджет RU для неробочого часу, автоматична пауза і продовження. | немає |

### Вкладка «Повтори»

| Поле (JSON) | Що це | Навіщо, ефект і результат | За замовчуванням |
|---|---|---|---|
| Спроб одного запиту (`retry.requestAttempts`) | Скільки разів усього робиться один запит до SharePoint (перша спроба + повтори при мережевих збоях, 5xx, 429 з паузою за `Retry-After`). | Більше — стійкіше до коротких збоїв, але довше чекання. 1…20. | 6 |
| Спроб одного файлу (`retry.fileAttempts`) | Скільки разів файл береться заново після тимчасової помилки чи конфлікту. | Після останньої — `failed:transient` / `failed:conflict`. 1…20. | 3 |
| Паузи між спробами файлу, хв (`retry.filePausesMinutes`) | Список через кому. | Пауза перед 2-ю, 3-ю… спробою; останнє значення діє далі. З 3 спробами використовуються перші дві паузи. | 1, 5, 15 |
| Хвиля заблокованих, хв (`retry.lockedWaveMinutes`) | Як часто повторювати відкладені (заблоковані, check-out) файли. | — | 10 |
| Чекати заблоковані, хв (`retry.lockedLimitMinutes`) | Скільки максимум чекати, поки файл звільниться. | Далі — `failed:locked`; повтор вручну пізніше. | 120 |
| Запобіжник: останніх файлів (`retry.breakerWindow`) | Скільки останніх результатів обробки враховує запобіжник (проміжні невдалі спроби теж рахуються). | — | 50 |
| Запобіжник: частка помилок (`retry.breakerFailureRatio`) | Частка тимчасових, доступу і внутрішніх помилок у вікні, що зупиняє прогін. | Масова проблема (мережа, SharePoint, права) зупиняє прогін, а не «спалює» всі файли в помилки. 0…1. | 0,5 |
| Помилок доступу поспіль до зупинки (`retry.authFailuresToStop`) | 401/403 поспіль. | Відкликаний доступ чи прострочений сертифікат зупиняє прогін. | 10 |
| Лише 503 стільки хв — блокування (`retry.blockedMinutes`) | Як довго лише 503 означають можливе блокування застосунку. | Прогін зупиняється з причиною «можливе блокування SPO», без подальших спроб. | 15 |

### Вкладка «Підключення»

| Поле (JSON) | Що це | Навіщо, ефект і результат | За замовчуванням |
|---|---|---|---|
| Підключення (`connections`) | Одне чи кілька підключень. | Яким застосунком працювати. Кілька — лише з пулом. | — |
| Пул застосунків (`pool.enabled`) | Кілька застосунків в одному прогоні. Вмикається з попередженням. | Кожен застосунок має свій бюджет і стан throttling. Файл від початку до кінця обробляє один застосунок. Пауза одного не зупиняє інші. Перед стартом перевіряється, що кожен застосунок бачить усі цілі. | вимкнено |
| Стеля тенантного бюджету, % (`pool.tenantCeilingPercent`) | Частка ліміту всього тенанта, яку може використати весь пул. | Захист користувачів і інших застосунків. 1…100. | 50 |

## 3.4. Новий прогін

**Прогони → Новий прогін** або **Профіль → Запустити…**

| Поле | Що це | Навіщо, ефект і результат |
|---|---|---|
| Профіль | Профіль прогону. | Профіль перевіряється одразу; помилки видно в діалозі, з ними прогін не запуститься. |
| Режим | Див. таблицю нижче. | Визначає, чи буде запис. |
| Разові зміни для цього прогону | Завантажень, обробників, вивантажень, бюджет RU, процесів Excel, маски включення/виключення, місця Hyperlinks / Link Sources / Формули, «Працювати лише у вікнах». **Скинути до профілю** — прибрати зміни. | Змінити параметри одного прогону, не змінюючи профіль. Зміни потрапляють у знімок прогону. |
| Оцінка кількості файлів | За останнім переліком: усього файлів Excel і скільки під фільтрами. | Щоб знати масштаб до старту. |
| Підтверджую запис… (лише apply) | Прапорець. | Без нього apply не запуститься. |

| Режим | Що робить | Запис у SharePoint | Результат |
|---|---|---|---|
| **inventory** | Перелік файлів, завантаження й розбір кожного файлу, усі посилання і гістограма префіксів. За вартістю — як scan. | Ні | Звіт «Префікси», кількість файлів для профілю; статуси як у scan. |
| **scan** | Повна обробка в пам'яті. | Ні | Що буде замінено: статуси `planned`, звіти «Посилання», «Вибірка», «Залишки». |
| **apply** | Заміна і запис змінених файлів. | Так | `done` — записано, `unchanged` — змінювати нічого. |
| **verify** | Повторне завантаження і пошук старих адрес у всіх файлах профілю. | Ні | `verified` — чисто; `changes_pending` — ще є що міняти. |

Кнопка **Перевірити (verify)** на картці прогону apply перевіряє лише файли, записані цим прогоном ([докладно](#кнопка-перевірити-verify)).

## 3.5. Повторний прогін

**Картка прогону → Повторити…**, група помилок → ↻, або **Файли → Повторити вибрані / Повторити все за фільтром**.

| Поле | Що це | Навіщо, ефект і результат | За замовчуванням |
|---|---|---|---|
| Статуси | Статуси файлів батьківського прогону. `failed` — усі помилки, `done` — і `done:residual` тощо. **`attention — потребують уваги`** — усе, що рахує картка «Потребують уваги»: помилки, файли із залишками (`*:residual`), `needs_excel`, `changes_pending`, `skipped:encrypted`. | Які файли взяти. Залишки й `skipped:encrypted` повторювати має сенс лише після доповнення правил (прапорець «Взяти поточну версію профілю») чи зняття пароля. | `failed` |
| Класи помилок | transient, conflict, locked, excel, auth, file, validation, internal. | Звузити вибір. | усі |
| Розширення | Через кому. | Наприклад, лише `.xls` після встановлення Excel. | усі |
| Маска шляху | `*` і `?`. На відміну від фільтрів профілю: від кореня бібліотеки (не цілі) і з урахуванням регістру. | Лише частина папок, наприклад `Fin/2024/*`. | — |
| Режим | inventory / scan / apply / verify. | Наприклад, повторити scan із новими правилами перед apply. | як у батьківському |
| Взяти поточну версію профілю | Прапорець. | Повтор із доповненими правилами або іншими параметрами. Цілі мають збігатися з батьківським прогоном. Без прапорця — знімок батьківського прогону. | вимкнено |

Проігноровані файли не беруться. Кожен файл завантажується заново зі свіжою версією. Результат — новий прогін з позначкою «повтор прогону N».

## 3.6. Дашборд і картка прогону

**Заголовок:**
- номер прогону, стан (виконується, пауза, зупинено, перервано, завершено, завершено з помилками), режим, профіль, «повтор прогону N»;
- для зупиненого чи перерваного — причина.

**Прогрес:** оброблено N з M (%), початок, тривалість, орієнтовний час до завершення (за поточною швидкістю).

**Картки:**

| Картка | Що показує | На що дивитися |
|---|---|---|
| Знайдено файлів | Скільки файлів у прогоні (під час переліку росте). | — |
| Змінено | apply — записано в SharePoint; scan — буде змінено. | — |
| Ще треба змінити (verify) | Файли, де verify знайшов адреси, які apply ще змінив би. | Має бути 0. Інакше — apply для цих файлів. |
| Без змін | Файли, де нічого змінювати не треба. | — |
| Замін посилань | Скільки посилань замінено; у підказці — за місцями. | — |
| Помилки | Файли з `failed:*`; у підказці — за класами. Клік по картці — вкладка помилок лише з помилками. | [С8](#с8-помилки-і-повтори) |
| Відкладено | Заблоковані файли, що чекають наступної хвилі. | Якщо їх багато вдень — працюйте в неробочий час. |
| З залишками | Файли зі старими адресами після заміни. | [С9](#с9-залишки-старих-адрес) |
| Потребують уваги | Помилки + залишки + needs_excel + changes_pending + skipped:encrypted. Клік по картці — вкладка помилок лише з цими файлами. | Детальний список — звіт «Потребують уваги» ([3.10](#310-звіти)). |
| Швидкість | Файлів за хвилину, МБ/с. | — |
| Активні обробники | Скільки файлів зараз в обробці; стан throttling. | «пауза» — SharePoint попросив почекати. |
| Excel (xls, xlsb) | Зайнято / запущено з N; операцій, зависань, падінь, закритих діалогів (якщо були); або «недоступний» з причиною. | Багато зависань — збільште таймаут Excel або перевірте файли. Закриті діалоги — див. [С10](#с10-файли-xls-і-xlsb-excel). |

**Навантаження на SharePoint** — рядок на кожен застосунок і рядок тенанта:

| Стовпець | Що це |
|---|---|
| Бюджет RU за хвилину | Яка частка хвилинного бюджету зайнята зараз. |
| RU за 24 год, RU усього | Витрачено за добу і з моменту останнього запуску прогону (після «Продовжити прогін» рахунок починається з нуля; підсумок за всі запуски — у звіті пілоту). |
| Запитів | Скільки запитів зроблено. |
| 429 / 503 | Скільки разів SharePoint просив почекати або був перевантажений. |
| Паралельність | Поточна межа одночасних запитів (знижується після 429 і поступово відновлюється). |
| Файлів зараз | Скільки файлів обробляє застосунок. |
| Стан | працює / пауза до ЧЧ:ММ:СС / можливе блокування. |
| Тенант (стеля пулу) | Скільки тенантного бюджету за 5 хв використовує прогін. |

**Динаміка** (знімок раз на хвилину):
- «Прогрес» — знайдено й оброблено файлів;
- «Швидкість і помилки» — файлів за хвилину між сусідніми знімками (а не середнє від початку, тож сповільнення видно одразу); на правій шкалі:
  - «Файлів з помилкою» — файли, що зараз у стані `failed:*` (те саме число, що в картці «Помилки», з запізненням до хвилини);
  - «Повторів» — невдалі спроби, після яких файл пішов на ще одну (тимчасова помилка, заблокований файл, повтор після Excel); багато повторів без росту помилок — SharePoint чи мережа не встигають, варто зменшити паралельність;
  - 429/503 — з моменту останнього запуску прогону;
- наведіть мишу — під графіком значення в цю мить;
- виділіть ділянку мишею — обидва графіки збільшаться до неї; кнопки «1 год», «6 год», «24 год» показують останній проміжок і далі рухаються з новими знімками; «Усе» або подвійний клік — увесь прогін;
- розрив лінії швидкості — у цей час прогін не працював (пауза, програму закрито).

**Розбивки:**
- за форматами — таблиця: усього, оброблено, змінено, помилок;
- за цілями — блок на кожну бібліотеку: назва (і папка), адреса сайту, частка оброблених, ті самі числа.

**Кнопки:**
- **Пауза / Продовжити / Зупинити** — [С11](#с11-пауза-зупинка-закриття-вікна-перезавантаження);
- **Запустити / Продовжити прогін** — для створеного, зупиненого або перерваного прогону. Для apply — з підтвердженням;
- **Повторити…** — [3.5](#35-повторний-прогін);
- **Перевірити (verify)** — для завершеного apply, [див. нижче](#кнопка-перевірити-verify);
- **Звіти** — [3.10](#310-звіти).

**Вкладки картки прогону:**
- **Огляд** — дашборд;
- **Файли**, **Помилки й увага** — [3.7](#37-таблиця-файлів-помилки-картка-файлу);
- **Налаштування прогону** — знімок профілю, шаблонів і підключень, з якими прогін працює.

### Кнопка «Перевірити (verify)»

**Мета:** переконатися, що в SharePoint зараз лежать саме виправлені файли і старих адрес у них не лишилось. Кнопка є на картці завершеного прогону **apply** (зокрема завершеного з помилками).

**Що відбувається після натискання:**

1. Створюється новий прогін у режимі `verify` з позначкою «повтор прогону N» і одразу запускається; відкривається його картка.
2. У прогін потрапляють **лише файли зі статусом `done`** — ті, що цей apply записав. Файли без змін, з помилками, відкладені й проігноровані не беруться. Бібліотека заново не перелічується.
3. Для кожного файлу береться **поточна версія з SharePoint** (свіжі метадані й завантаження), а не копія з apply. Тож якщо після apply хтось перезаписав файл, verify це побачить.
4. Файл обробляється тими самими правилами — зі знімка профілю прогону apply, а не з поточного профілю. xls і xlsb, як і в apply, проходять через Excel ([С10](#с10-файли-xls-і-xlsb-excel)).
5. **Нічого не записується.** Verify лише рахує, що змінив би apply.

**Результат для кожного файлу:**

| Статус | Що означає | Що робити |
|---|---|---|
| `verified` | Правилам нема що міняти: старих адрес, які покривають правила, немає. | — |
| `changes_pending` | Є посилання, які apply змінив би. Найчастіше файл перезаписали після apply (стара копія, відновлена версія). | **Повторити…** з режимом apply і статусом `changes_pending`. |
| `…:residual` | Додатково до статусу: у файлі є старі адреси, яких жодне правило не покриває. | [С9](#с9-залишки-старих-адрес) |
| `failed:<клас>` | Файл не вдалося перевірити (доступ, файл видалено, Excel тощо). | [3.9](#39-класи-помилок-і-що-робити) |

На дашборді verify з'являється картка **Ще треба змінити** — кількість `changes_pending`. Очікуваний результат: 0 у цій картці і 0 залишків, крім узгоджених.

**Скільки коштує:** як scan за тими самими файлами — кожен файл завантажується й розбирається, витрачаючи RU. Для великого apply запускайте verify в неробочий час.

**Відмінність від verify за профілем:** **Новий прогін → verify** (або `verify --profile <профіль>` у CLI) перелічує і перевіряє всі файли профілю, зокрема ті, що apply не змінював. Кнопка на картці перевіряє лише записане цим прогоном. Те саме з командного рядка — `verify <прогін apply>` ([3.11](#311-командний-рядок-cli)).

## 3.7. Таблиця файлів, помилки, картка файлу

**Файли:**
- **фільтри** — статус (зокрема `attention — потребують уваги`, як у [3.5](#35-повторний-прогін)), клас помилки, формат, ціль, пошук за шляхом;
- **сортування** — клік по заголовку;
- **дії з вибраними файлами** (прапорці) — **Повторити вибрані**, **Ігнорувати вибрані** (з коментарем);
- **Повторити все за фільтром** — переносить у діалог повтору лише вибрані статуси; клас, формат і маску задайте в діалозі;
- **CSV / XLSX** — експорт поточного вигляду з фільтрами;
- клік по рядку — картка файлу.

**Помилки й увага:** групи «статус + повідомлення» з кількістю файлів, класом і рекомендацією. Дії групи: ☰ файли, ↻ повторити, ⊘ ігнорувати. Перемикач над таблицею: **Усе** (ще й відкладені), **Помилки** (`failed:*`), **Потребують уваги** (те, що рахує однойменна картка). Вкладка і перемикач видно в адресі, тож картки дашборда відкривають саме свій список.

**Картка файлу:**

| Розділ | Що показує |
|---|---|
| Кнопки | **Відкрити в SharePoint**; **Зберегти версію до зміни** (копія версії до запису); **Ігнорувати** (з коментарем — файл не братиметься в повтори і рахується окремо). |
| Метадані | Розмір, хто і коли змінив у SharePoint, спроб, застосунок, версія до запису, eTag після запису, клас помилки, повідомлення, коментар. |
| Історія спроб | Кожна спроба: час, номер, етап (download, process, excel, upload), результат, HTTP-код, `request-id` (для звернення в підтримку Microsoft), застосунок. |
| Посилання | Кожне знайдене посилання: дія, місце, частина файлу, старе значення (і як розв'язано відносне), нове значення, номер правила. |
| Залишки | Частина файлу, кодування, збіг, контекст. |

Дії з посиланнями:

| Дія | Значення |
|---|---|
| Replaced | Замінено (або буде замінено в scan). |
| NoRule | Правила для адреси немає — не змінено. |
| Current | Уже нова адреса — не змінено. |
| Unresolved | Відносне посилання, яке не вдалося розв'язати (немає старої адреси цілі чи `baseHost`). |
| PlaceDisabled | Правило є, але місце заміни вимкнене в профілі — не змінено, стане залишком. |

Місця посилань: гіперпосилання, Link Sources, формули, кеш формул (кешований результат формули), інші зовнішні, шлях збереження (де Excel зберігав файл востаннє — оновлюється разом з іншими змінами, але сам по собі не привід записувати файл).

## 3.8. Статуси

**Статуси файлу — фінальні:**

| Статус | Значення | Що робити |
|---|---|---|
| `done` | Змінено і записано в SharePoint. | — |
| `unchanged` | Змінювати нічого не треба. | — |
| `planned` | scan: буде змінено. | apply |
| `verified` | verify: старих адрес немає. | — |
| `changes_pending` | verify: є адреси, які apply змінив би. | apply для цих файлів |
| `needs_excel` | Потрібен Excel, а його немає або 0 процесів. | Повтор на машині з Excel |
| `ignored` | Позначено вручну з коментарем. | — |
| `skipped:filtered` | Не пройшов фільтри (шлях, дата, мінімальний розмір). | — |
| `skipped:too_large` | Більший за максимальний розмір. | Збільшити ліміт і повторити, якщо треба |
| `skipped:encrypted` | Захищений паролем на відкриття або на зміну; або Excel запитав пароль. | Зняти пароль і повторити ([С10а](#с10а-файли-з-паролем)) |
| `skipped:deleted` | Видалений або переміщений після переліку. | — |
| `failed:<клас>` | Помилка, див. [3.9](#39-класи-помилок-і-що-робити). | — |

**Суфікси:** `:residual` — у файлі лишилися старі адреси ([С9](#с9-залишки-старих-адрес)); `:needs_excel` — частину файлу може виправити лише Excel.

**Проміжні статуси:** `pending` (у черзі), `in_progress` (в обробці), `deferred` (заблокований, чекає хвилі), `waiting_path` (перелік ще не дійшов до папки файлу).

**Стани прогону:**

| Стан | Значення |
|---|---|
| створено | Ще не запускався. |
| виконується / пауза | — |
| зупинено | Зупинено вручну; можна продовжити. |
| перервано | Зупинено запобіжником, через збій переліку, доступу чи блокування; причина на дашборді. Можна продовжити після усунення причини. |
| завершено | Усі файли мають фінальний статус, помилок немає. |
| завершено з помилками | Усі файли мають фінальний статус, є `failed:*`. |

## 3.9. Класи помилок і що робити

| Клас | Приклади | Автоповтор | Що робити |
|---|---|---|---|
| тимчасова (`transient`) | Обрив мережі, 5xx, 429 після вичерпання повторів, таймаут | Так, до 3 спроб файлу | Повторити |
| конфлікт (`conflict`) | 412: файл змінили під час обробки | Так, з новою версією | Повторити |
| заблоковано (`locked`) | 423, check-out, файл відкритий | Так, хвилями до 2 год | Попросити власника закрити файл або повернути check-out; повторити пізніше |
| Excel (`excel`) | Excel завис або впав | Так, 1 раз у новому процесі | Перевірити файл вручну; збільшити таймаут Excel |
| доступ (`auth`) | 401, 403 | Ні | Перевірити права застосунку на сайт і сертифікат; повторити |
| файл (`file`) | Пошкоджений, не Excel, непідтримуваний формат | Ні | Перевірити вручну або ігнорувати |
| самоперевірка (`validation`) | Результат не пройшов перевірку; посилання на локальний диск у xls/xlsb ([С10](#с10-файли-xls-і-xlsb-excel)) | Ні | Файл не змінено. Прочитати повідомлення; передати файл розробнику |
| внутрішня (`internal`) | Помилка самого застосунку | Ні | Передати розробнику журнал; повторити |

## 3.10. Звіти

**Картка прогону → Звіти** (CSV або XLSX; підсумок і звіт пілоту — TXT) або `spo-replace-link export <прогін> -o <папка>`.

| Звіт | Що в ньому | Для чого |
|---|---|---|
| Файли (`files`) | `id`, `path`, `format`, `size`, `status`, `error_class`, `error`, `attempts`, `replacements`, `residuals`, `version_before`, `etag_after`, `app`, `comment` | Повний перелік і архів; `version_before` — для відкату. |
| Посилання (`links`) | `path`, `part`, `kind`, `action`, `old_value`, `new_value`, `rule`, `resolved_from` | Що замінено чи буде замінено, яким правилом. |
| Залишки (`residuals`) | `path`, `part`, `encoding`, `match`, `context` | Що лишилося невиправленим і де. |
| Потребують уваги (`attention`) | `id`, `path`, `status`, `error_class`, `message`, `attempts`, `action` | Список дій: що робити з кожним файлом. |
| Префікси (`prefixes`) | `prefix`, `links`, `files`, `replaced`, `no_rule`, `unresolved` | Доповнення правил ([С4](#с4-інвентаризація-і-доповнення-правил)). |
| Вибірка для перевірки (`sample`) | `id`, `path`, `status`, `replacements`, `residuals`, `version_before`, `url`, `examples` (до трьох замін), `checked`, `comment` | Ручна перевірка 30 змінених файлів. Вибір випадковий, але для того самого прогону завжди той самий. |
| Підсумок (`summary`) | Тривалість, файли, обсяг, заміни, швидкість, кількість за статусами | Короткий звіт. |
| Звіт пілоту (`pilot`) | Файли за форматами; RU, 429/503, RU на файл (за всі запуски прогону); швидкість за час активної обробки, с на файл, межа бюджету RU, прогноз на 10 000 файлів і на профіль; поведінка SharePoint при записі; спроби з конфліктом і блокуванням; Excel; помилки з рекомендаціями; що перевірити вручну | Висновок пілоту і планування бойового прогону ([С6](#с6-пілот-на-одній-бібліотеці)). |

## 3.11. Командний рядок (CLI)

`spo-replace-link <команда>`. Команди, що працюють із SharePoint, виконуються через застосунок, відкритий **під тим самим обліковим записом**. Адресу і ключ API CLI бере з `api.json` у папці даних застосунку (`--data`, змінна `SPO_RL_DATA`, за замовчуванням `%LOCALAPPDATA%\SPOReplaceLink`; якщо застосунок запущено з `--data`, передайте ту саму папку). `--host` (змінна `SPO_RL_HOST`) задає адресу явно; без `api.json` — `http://localhost:5080`.

| Команда | Що робить |
|---|---|
| `profiles\|connections\|templates list` | Список. |
| `… get <назва> [-o файл.json]` | Показати або експортувати. |
| `… import <файл.json> [--name]` | Створити або замінити. |
| `… delete <назва>` | Видалити. |
| `profiles validate <назва>` | Перевірити профіль як перед запуском. |
| `connections test <назва> [--profile <профіль>]` | Токен і доступ до цілей профілю. |
| `inventory\|scan\|apply <профіль> [--wait] [--yes]` | Новий прогін; `--wait` — чекати з прогресом; `--yes` — без запитання для apply. |
| `verify <прогін apply>` або `verify --profile <профіль>` | Перевірити файли прогону або весь профіль. |
| `retry <прогін> [--status …] [--class …] [--ext …] [--path-mask …] [--file-id …] [--list файл.csv] [--mode …] [--current-profile]` | Повторний прогін за вибором. `--status attention` — усі файли, що потребують уваги. `--list` — CSV зі шляхами (стовпець `path` або перший). |
| `runs [--take N]`, `status <прогін>`, `wait <прогін>` | Список, стан, очікування. |
| `start\|pause\|resume\|stop <прогін>` | Керування. |
| `files <прогін> [--status] [--class] [--search] [--take]` | Файли прогону. |
| `ignore <файл> --comment "…"` | Ігнорувати файл. |
| `delete-run <прогін> [--yes]` | Видалити прогін, що не виконується, з усіма результатами ([С11](#с11-пауза-зупинка-закриття-вікна-перезавантаження)). Питає підтвердження. |
| `export <прогін> -o <папка> [--prefix-depth N]` | Усі звіти ([3.10](#310-звіти)); `--prefix-depth` — глибина префіксів у `prefixes` (1–10, за замовчуванням 2). |
| `rules validate -c профіль.json`, `rules test -c профіль.json <посилання…> [--base-url]` | Перевірка правил без застосунку. |
| `local <папка> -c профіль.json [--write --out] [--base-url] [--excel N] [--temp] [--report] [--parallel] [--csv-delimiter]` | Локальна обробка ([С14](#с14-обробка-локальної-папки-без-sharepoint)). |

Ctrl+C під час `--wait` плавно зупиняє прогін. Коди виходу: `0` — добре, `1` — є що потребує уваги, `2` — помилка налаштувань чи застосунок недоступний, `3` — прогін зупинено або перервано.

## 3.12. Файли і папки застосунку

У папці даних (`--data`):

| Шлях | Що це |
|---|---|
| `state.db` | База: налаштування, прогони, файли, спроби, заміни, залишки, метрики. Резервна копія — коли застосунок закритий. |
| `logs\host-*.jsonl` | Журнал (JSON lines): кожна помилка з деталями. Передається розробнику при проблемах. |
| `temp\` | Тимчасові копії файлів; кожен файл видаляється одразу після обробки. |
| `temp\excel-*.pids` | Службові: процеси Excel, запущені застосунком (щоб прибрати їх після аварійного завершення). |
| `api.json` | Адреса і ключ локального API запущеного екземпляра — для CLI. Створюється при запуску, видаляється при виході. |

## 3.13. Обмеження

- **Не виправляються** (лише потрапляють у звіт залишків): pivot-кеші, підключення до даних, Power Query, текст клітинок, шляхи у VBA-коді, посилання виду `AllItems.aspx?id=…` і `/:x:/r/…`.
- **Поля Modified і Modified By змінюються:** запис файлу створює нову версію від імені застосунку.
- **Масового відкату немає** — лише вручну за журналом версій ([С12](#с12-повернути-попередню-версію-файлу)).
- **Правила лише префіксні** (без регулярних виразів і змінних).
- **Імпорт зі списку ReplaceMagic** читає два стовпці або «старе → нове»; точний формат Export list ще уточнюється.
- **Пароль і Excel.** Файли з паролем не обробляються, лише позначаються для повтору ([С10а](#с10а-файли-з-паролем)). xls і частина xlsb потребують Excel на машині, тому застосунок працює в сесії користувача, а не як служба Windows.
- **xls/xlsb з посиланням на локальний диск** — див. [С10](#с10-файли-xls-і-xlsb-excel).
- **Доступ до вікна** — лише на локальній машині; ролей і входу через Entra для GUI немає.

## 3.14. Якщо щось пішло не так

| Ситуація | Причина і що робити |
|---|---|
| «Сертифікат … не знайдено у сховищі» | Застосунок запущено під іншим обліковим записом, ніж той, під яким створено сертифікат, або вибрано не те сховище. |
| «без закритого ключа» | У вибраному сховищі лише імпортований `.cer` без ключа. Виберіть сховище, де сертифікат створено командою `New-SelfSignedCertificate`, або створіть новий сертифікат. |
| «Немає доступу до закритого ключа» | Сертифікат у `LocalMachine`, а обліковому запису застосунку не видано Read на ключ (Manage Private Keys). |
| `AADSTS700027`, `AADSTS700016` | Сертифікат не завантажено в застосунок Entra, або хибний Client ID чи тенант. |
| Токен є, але `403` на ціль | Немає згоди адміна на Sites.Selected або не видано `write` на сайт. |
| Пошук сайту нічого не знаходить | Нормально для Sites.Selected — введіть адресу сайту. |
| Прогін «перервано: Запобіжник…» | Масова проблема: мережа, SharePoint, права. Прочитайте причину, усуньте, **Продовжити прогін**. |
| «можливе блокування SPO» | SharePoint тривалий час відповідає лише 503. Не продовжуйте одразу; зачекайте, знизьте бюджет RU, працюйте в неробочий час. |
| Багато 429 | Знизьте бюджет RU, перевірте діапазон ліцензій у підключенні, з'ясуйте, чи не працюють паралельно інші важкі застосунки (міграція, бекап). |
| Багато `deferred` / `failed:locked` | Файли відкриті користувачами. Працюйте в неробочий час; повторіть пізніше. |
| `needs_excel` | Excel не встановлено, не активовано для цього облікового запису, або 0 процесів у профілі. |
| `failed:validation` у xls/xlsb з «літерою диска» | [С10](#с10-файли-xls-і-xlsb-excel): папка даних на іншому диску. |
| CLI: «Хост недоступний» | Застосунок не запущено під цим обліковим записом, або його запущено з іншою `--data` (передайте ту саму в CLI), або явний `--host` вказує не туди. |
| CLI: «Немає ключа доступу до цього екземпляра» | За цією адресою працює застосунок іншого користувача або іншої папки даних. Запустіть застосунок під своїм записом і приберіть `--host`, або вкажіть ту саму `--data`. |
| Вікно не відкривається, повторний запуск нічого не робить | Застосунок уже працює (можливо, у треї). Подвійний клік по іконці біля годинника. |
| Будь-що незрозуміле | `spo-replace-link export <прогін> -o …` і `logs\host-*.jsonl` з папки даних — розробнику. |
