# SPOReplaceLink

Заміна битих посилань в Excel-файлах (xlsx, xlsm, xlsb, xls) після міграції в SharePoint Online.
**Інструкція користувача — [docs/USER_GUIDE.md](docs/USER_GUIDE.md)**: сценарії від першого налаштування до бойового прогону, довідник усіх полів, статуси, звіти, CLI. Та сама інструкція вбудована в застосунок: розділ «Довідка» (дерево розділів, пошук) і кнопки «?» на екранах і вкладках профілю.
Вимоги — [docs/FEATURES.md](docs/FEATURES.md), план — [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md).

MVP (етапи 1–5) реалізовано:

- рушій правил і обробка OOXML без Excel;
- робота з SharePoint через Microsoft Graph: перелік (delta), завантаження, запис з `If-Match`, upload session;
- база стану, повтори трьох рівнів, відкладені файли, запобіжник;
- облік навантаження (бюджет RU, throttling на рівні застосунку, вікна роботи, виявлення блокування) і пул застосунків;
- десктопний застосунок: дашборд прогону, файли, помилки, повтори, налаштування профілів, шаблонів правил і підключень;
- CLI для розкладу й автоматизації;
- xls і залишки xlsb через Excel в окремих процесах;
- інструменти пілоту: звіт пілоту (вартість RU на файл, прогноз часу, поведінка SharePoint при записі) і вибірка файлів для ручної перевірки.

Пілот на реальному тенанті ще попереду — порядок і критерії в [інструкції, сценарій С6](docs/USER_GUIDE.md#с6-пілот-на-одній-бібліотеці).

## Як це влаштовано

**SPOReplaceLink.exe** — один десктопний застосунок, з якого керується все: налаштування, запуск прогонів, дашборд, помилки й повтори. Рушій працює всередині застосунку.

- **Дані.** База стану (`state.db`, SQLite), журнал (`logs/host-*.jsonl`) і тимчасові файли лежать у папці даних: `--data`, за замовчуванням `%LOCALAPPDATA%\SPOReplaceLink`. На одну папку даних працює один екземпляр; повторний запуск відкриває вже запущене вікно.
- **Закриття вікна під час прогону.** Застосунок запитає, що робити:
  - згорнути в трей — прогін триває, вікно відкривається подвійним кліком по іконці біля годинника;
  - зупинити прогін і вийти — поточні файли завершаться, решта лишиться в черзі.
- **Продовження.** Після наступного запуску зупинений прогін продовжується кнопкою «Продовжити прогін». Перерваний збоєм або перезавантаженням прогін застосунок продовжує сам, з того самого місця.
- **CLI.** Поки застосунок відкритий, він слухає локальний API на `http://localhost:5080`, а якщо порт зайнятий (інший користувач машини) — на вільному порту. Адресу і ключ доступу він пише в `api.json` у папці даних; CLI того ж користувача бере їх звідти і через API запускає прогони за розкладом. Запити без ключа API відхиляє, тож кілька користувачів однієї машини працюють незалежно.

```bash
SPOReplaceLink.exe --data D:\SPOReplaceLink
```

`--selftest <файл>` — запустити, перевірити, що вікно й розділи відкриваються, записати результат у файл і вийти (для перевірки встановлення без погляду на екран).

## xls і xlsb через Excel

xlsx, xlsm і посилання xlsb у `.rels` обробляються без Excel. Через Excel ідуть:
- файли xls;
- файли xlsb, у бінарних записах яких лишилися старі адреси (наприклад, формула `HYPERLINK`).

Як це працює:
- **Окремі процеси.** Excel працює в окремих процесах `SPOReplaceLink.ExcelWorker.exe`, лише з локальною копією файлу. Він прихований, без діалогів, без оновлення зв'язків, макроси вимкнено.
- **Заміна без `ChangeLink`.** Excel зберігає копію як xlsm, посилання в ній замінює той самий рушій, що й для xlsx, і Excel зберігає результат назад в оригінальному форматі. Excel-івський `ChangeLink` не використовується: він одразу перечитує нове джерело, і якщо воно недоступне з цієї машини (SharePoint), кешовані значення стають `#REF!`.
- **Перевірка в Excel.** Записаний файл відкривається в Excel ще раз. Якщо Edit Links, гіперпосилання чи формули ще містять старі адреси, файл отримує позначку `:residual`.
- **Пул процесів.** Кількість процесів Excel (за замовчуванням 2; 0 — без Excel) і таймаут задаються на вкладці «Продуктивність» профілю.
- **Зависання.** Якщо Excel не відповідає довше за таймаут, процес завершується примусово, а файл отримує ще одну спробу в новому процесі. Якщо й вона не вдалася — `failed:excel`. Інші файли обробляються далі.
- **Після прогону** процесів Excel не лишається. Процеси, що лишилися після аварійного завершення застосунку, завершуються під час наступного запуску. Це стосується лише процесів, які запустив сам застосунок; Excel користувача не зачіпається.
- **Без Excel** (не встановлено або 0 процесів) файли отримують `needs_excel`, і їх можна обробити пізніше повторним прогоном.
- **Посилання на локальний диск.** Посилання на файл на тому самому диску, що й тимчасова папка (папка даних, за замовчуванням на C:), Excel зберіг би без літери диска. Такий файл не записується: він отримує `failed:validation` з поясненням. Щоб його обробити, візьміть папку даних на іншому диску (`--data D:\…`) або `local --temp D:\…`. Посилань на SharePoint, мережеві шляхи та інші диски це не стосується.

## Інтерфейс

- **Дашборд** — поточний або останній прогін:
  - лічильники: знайдено, змінено, без змін, замін за місцями, помилки за класами, відкладені, з залишками, потребують уваги;
  - прогрес і орієнтовний час до завершення, швидкість;
  - навантаження на SharePoint по кожному застосунку і тенанту (RU, 429/503, паузи);
  - графіки з масштабуванням (виділення мишею, останні 1 / 6 / 24 год), розбивки за форматами й цілями;
  - кнопки: пауза, продовжити, зупинити, повторити, перевірити (verify).
- **Прогони** — список і новий прогін з профілю. Профіль перевіряється перед стартом; для apply потрібне підтвердження з оцінкою кількості файлів.
- **Картка прогону:**
  - «Файли» — фільтри, пошук, виділення, повтор чи ігнорування вибраних, експорт поточного вигляду в CSV/XLSX (через «Зберегти як»);
  - «Помилки й увага» — групи за статусом і повідомленням з рекомендацією і груповими діями;
  - «Налаштування прогону» — знімок профілю.
- **Профілі:**
  - вкладки «Загальне і правила», «Цілі» (сайт за URL або пошуком, бібліотека зі списку, дерево папок), «Фільтри» (з підрахунком за останнім переліком), «Місця заміни», «Продуктивність» (пресети, вікна роботи), «Повтори», «Підключення» (пул з попередженням);
  - клонування, імпорт і експорт JSON.
- **Шаблони правил** — таблиця з перевіркою під час введення (дублікати, конфлікти, цикли, повторні заміни), перевірка посилання, імпорт з CSV/XLSX чи зі списку ReplaceMagic, експорт у CSV.
- **Підключення** — тенант, Client ID, сертифікат зі сховища Windows, діапазон ліцензій з лімітами, перевірка доступу до цілей профілю.

Подивитися застосунок без SharePoint можна на демо-даних. Утиліта `tools/SPOReplaceLink.DemoSeed` проганяє справжній рушій на емуляторі Graph і відкриває застосунок з тим самим емулятором — у ньому можна запускати нові прогони:

```bash
dotnet run --project tools/SPOReplaceLink.DemoSeed -- D:\Temp\spo-demo --open
```

- `--large 200000` додає синтетичний прогін на 200 тис. файлів.
- `--port` задає порт локального API для CLI (за замовчуванням 5097).
- Емульований SharePoint зберігається в `fake-sharepoint.json` у папці даних при закритті застосунку. Повторний запуск з тією самою папкою і `--open` відкриває все як було, тож зупинений прогін можна продовжити.
- Якщо на машині є Excel, у демо є справжній xls (`Fin/Звіт старий.xls`), який обробляється через Excel.

## Налаштування SharePoint (один раз)

SPOReplaceLink входить у SharePoint як застосунок Entra (app-only), без користувача: застосунок у Entra + сертифікат. Пароля чи секрету в налаштуваннях немає — закритий ключ сертифіката лежить лише у сховищі Windows на ВМ, в Entra завантажується тільки відкрита частина.

### 1. Сертифікат

Сертифікат ніде купувати не треба: для входу застосунку в Entra підходить самопідписаний. Його створюють на машині, де працюватиме SPOReplaceLink, **під тим обліковим записом, під яким його запускатимуть** (інакше застосунок не побачить ключ). Якщо в компанії є внутрішній центр сертифікації і політика вимагає його — можна видати сертифікат там; вимоги ті самі: RSA 2048+, із закритим ключем, у сховищі `My`.

**Варіант А — застосунок запускає звичайний користувач** (`certificateStore: "CurrentUser"`). PowerShell під цим записом, права адміністратора не потрібні:

```powershell
$cert = New-SelfSignedCertificate -Subject "CN=spo-replace-link-1" -CertStoreLocation Cert:\CurrentUser\My -KeyAlgorithm RSA -KeyLength 2048 -KeySpec Signature -KeyExportPolicy NonExportable -HashAlgorithm SHA256 -NotAfter (Get-Date).AddYears(2)
```

**Варіант Б — сертифікат спільний для кількох облікових записів машини** (`certificateStore: "LocalMachine"`). PowerShell від адміністратора, `Cert:\LocalMachine\My` замість `Cert:\CurrentUser\My`. Потім дати потрібним записам доступ до ключа: `certlm.msc` → Personal → Certificates → сертифікат → All Tasks → Manage Private Keys → додати запис з правом **Read**.

Далі в тому самому вікні PowerShell — відбиток для підключення і відкрита частина для Entra:

```powershell
$cert.Thumbprint
```

```powershell
Export-Certificate -Cert $cert -FilePath .\spo-replace-link-1.cer
```

`.cer` містить лише відкритий ключ, його можна передавати адміну Entra поштою. `NonExportable` означає, що закритий ключ не можна вивантажити з ВМ — для нової ВМ створюють новий сертифікат і додають його до застосунку. Знайти відбиток пізніше: `Get-ChildItem Cert:\CurrentUser\My` (або `LocalMachine\My`).

Сертифікат діє 2 роки. Перед завершенням створити новий, додати його до застосунку поруч зі старим, змінити відбиток у підключенні, потім видалити старий. Застосунок відмовляється від простроченого сертифіката з помилкою `failed:auth`.

### 2. Застосунок у Entra

Потрібен адмін Entra (Application Administrator або Global Administrator).

1. [Entra admin center](https://entra.microsoft.com) → **App registrations** → **New registration**: назва, наприклад `spo-replace-link-1`; **Accounts in this organizational directory only**; Redirect URI не потрібен.
2. На сторінці **Overview** записати **Application (client) ID** → `clientId` і **Directory (tenant) ID** → `tenantId` (або домен `…onmicrosoft.com`).
3. **Certificates & secrets** → **Certificates** → **Upload certificate** → файл `.cer` з кроку 1. Відбиток, показаний в Entra, має збігатися з `$cert.Thumbprint`.
4. **API permissions** → **Add a permission** → **Microsoft Graph** → **Application permissions** → **Sites.Selected** → **Add**. Дозвіл `User.Read` (Delegated), доданий за замовчуванням, можна видалити.
5. **Grant admin consent for …** — статус має стати зеленим «Granted».

Sites.Selected сам по собі не дає доступу до жодного сайту — лише до тих, які видано явно на наступному кроці.

### 3. Доступ до сайтів

На кожну колекцію сайтів, де лежать цільові бібліотеки, видати застосунку роль `write` (`read` замало для застосування змін). Робить адмін SharePoint або Global Administrator з дозволом `Sites.FullControl.All` — через Graph Explorer, PnP.PowerShell або Microsoft Graph PowerShell; покроково, з перевіркою і відкликанням доступу — [інструкція, 1.5, крок 3](docs/USER_GUIDE.md#крок-3-доступ-до-сайтів). Найкоротше — PnP:

```powershell
Grant-PnPEntraIDAppSitePermission -AppId <clientId spo-replace-link-1> -DisplayName spo-replace-link-1 -Site https://contoso.sharepoint.com/sites/Fin -Permissions Write
```

### 4. Підключення

Скопіювати [samples/connection.example.json](samples/connection.example.json), підставити `tenantId`, `clientId`, `certificateThumbprint`, `certificateStore` (`CurrentUser` або `LocalMachine`, як у кроці 1) і `licenses`. Для кількох застосунків у пулі — по файлу на кожен, з різними `name`. Імпортувати і перевірити: `test` отримує токен і пробує прочитати кожну ціль профілю.

```bash
spo-replace-link connections import samples/connection.example.json
```

```bash
spo-replace-link connections test spo-replace-link-1 --profile finance
```

**Якщо `test` не проходить:**
- «Сертифікат … не знайдено у сховищі» — застосунок запущено під іншим записом, ніж той, під яким створено сертифікат, або не той `certificateStore`;
- «без закритого ключа» — у вибраному сховищі лише імпортований `.cer`; виберіть сховище, де сертифікат створено, або створіть новий (`.cer` у сховище не імпортують);
- «Немає доступу до закритого ключа» — у варіанті Б обліковому запису застосунку не видано Read на ключ;
- `AADSTS700027` / `AADSTS700016` — сертифікат не завантажено в застосунок або хибний `clientId`/`tenantId`;
- токен є, але `403` на ціль — не дано згоду адміна на Sites.Selected або не видано `write` на цей сайт (крок 3).

## Профіль

JSON з правилами, цілями, фільтрами, місцями заміни, параметрами продуктивності і повторів. Приклад — [samples/finance.profile.json](samples/finance.profile.json). Профілі, підключення і шаблони правил зберігаються в застосунку (редагуються в його вікні; з CLI — `profiles|connections|templates import/get/list/delete`); `get -o file.json` — експорт.

**Правила:**
- `rules` — пари `old` → `new`. Порядок не має значення: спрацьовує правило з найдовшим старим префіксом, лише на межі сегмента шляху (`/Document` не зачіпає `/Documents`), без урахування регістру і способу кодування.
- Префікс може бути повною адресою (`https://…`, `\\сервер\…`, `C:\…`) або шляхом від кореня (`/sites/…`, тоді потрібен `baseHost`).
- `templates` — назви шаблонів, збережених у застосунку; їхні правила йдуть перед `rules`.
- Набір правил перевіряється на старті: дублікати, конфлікти, цикли, а також правила, результат яких інше правило змінило б при повторному прогоні.

**Що і де обробляти:**
- `targets` — сайт, бібліотека, необов'язкова папка. `oldLocation` — стара адреса цієї бібліотеки (для відносних посилань). Якщо не задано, стара адреса виводиться з правил, коли це однозначно.
- `filters` — `extensions`, маски `include`/`exclude` (`*`, `**`, `?`), `maxFileSizeMb`, `modifiedAfter`/`modifiedBefore`.
- `places` — `hyperlinks`, `linkSources`, `formulas`, `otherExternal`. Решта місць ще не реалізована.

**Підключення і навантаження:**
- `connections` — назви підключень. Більше одного працюють лише з `pool.enabled: true`. Microsoft не рекомендує кілька застосунків для однієї задачі, тому навантаження всього пулу обмежене `pool.tenantCeilingPercent` (за замовчуванням 50%) тенантного бюджету.
- `performance` — паралельність (`downloads`, `processors`, `uploads`), таймаути, `budgetPercent` (частка ліміту RU застосунку), вікна роботи `windows` з власним бюджетом, `onlyInWindows`, `timeZone`.
- `retry` — спроби запиту і файлу, паузи між спробами, хвилі для заблокованих файлів, запобіжник, час до висновку «застосунок заблоковано».

Ліміти RU визначаються з `licenses` підключення: діапазон ліцензій тенанта, за таблицею Microsoft. За потреби їх можна скоригувати вручну.

```bash
spo-replace-link profiles validate finance
```

**inventory** — перелік, статистика і гістограма префіксів усіх посилань (`prefixes.csv`), щоб доповнити правила:

```bash
spo-replace-link inventory finance --wait
```

**scan** — dry-run: що буде замінено:

```bash
spo-replace-link scan finance --wait
```

**apply** — заміна і запис. Записуються лише змінені файли, з `If-Match`, номер версії до запису фіксується:

```bash
spo-replace-link apply finance --wait
```

**verify** — повторне завантаження файлів, записаних прогоном 12, і пошук залишків:

```bash
spo-replace-link verify 12 --wait
```

**retry** — повтор невдалих файлів прогону 12 без нового переліку бібліотеки. Вибір можна звузити через `--status`, `--class`, `--ext`, `--path-mask`, `--file-id`, `--list file.csv`:

```bash
spo-replace-link retry 12 --class transient locked --wait
```

**Звіти** — `files`, `links`, `residuals`, `attention` (що потребує уваги і що з цим робити), `prefixes`, `sample` (вибірка змінених файлів для ручної перевірки), `summary`, `pilot` (звіт пілоту: RU на файл, 429/503, прогноз часу, чи віддає SharePoint номер версії і чи змінює файли при збереженні):

```bash
spo-replace-link export 12 -o reports\run-12
```

**Керування:**
- `status`, `runs`, `files <run> --status failed`;
- `pause`, `resume`, `stop`, `start` (продовжити зупинений);
- `ignore <file> --comment "…"` — файл не братиметься в наступні повтори;
- `delete-run <run> [--yes]` — видалити прогін, що не виконується, з усіма результатами (у SharePoint нічого не змінюється).

Ctrl+C під час `--wait` зупиняє прогін плавно: поточні вивантаження завершуються, решта файлів лишається в черзі до `start`.

**Статуси файлів:**
- `done`, `unchanged`, `planned`, `verified`, `changes_pending` (verify знайшов, що ще є що міняти);
- `needs_excel`, `ignored`;
- `skipped:filtered|too_large|encrypted|deleted`;
- `failed:transient|conflict|locked|excel|auth|file|validation|internal`;
- суфікси `:residual` і `:needs_excel`.

Проміжні статуси: `pending`, `in_progress`, `deferred` (заблоковані, чекають наступної хвилі).

**Коди виходу CLI:**

| Код | Значення |
|---|---|
| 0 | усе добре |
| 1 | є файли, що потребують уваги |
| 2 | помилка в профілі, параметрах або відповіді застосунку (чи він не запущений) |
| 3 | прогін зупинено або перервано до завершення |

## Локальна обробка без SharePoint

Перевірити правила, подивитися результат для посилання, обробити локальну папку (за замовчуванням dry-run; `--write --out` пише змінені копії, вхідні файли не змінюються). `--base-url` — стара адреса папки, від якої розв'язуються відносні посилання. `--excel N` — кількість процесів Excel для xls і залишків xlsb (за замовчуванням — з профілю; `0` — без Excel). `--temp` — тимчасова папка (див. «Посилання на локальний диск»). Профіль для `local` не повинен посилатися на шаблони застосунку.

```bash
spo-replace-link rules validate -c samples/finance.profile.json
```

```bash
spo-replace-link rules test -c samples/finance.profile.json "https://contoso.sharepoint.com/Document/Analytics/a.xlsx"
```

```bash
spo-replace-link local D:\Copies\Fin -c samples/finance.profile.json --base-url https://contoso.sharepoint.com/Document/Fin --out D:\Fixed\Fin --write
```

## Перевірка в Excel

`tests/excel` — скрипти для машини з Excel:
- `New-ExcelFixtures.ps1` створює справжні xlsx/xlsm/xlsb/xls з посиланнями на старе розташування;
- `Test-ExcelOutput.ps1` відкриває оброблені файли в Excel і перевіряє Edit Links, гіперпосилання, формули і що зовнішній зв'язок читає дані з нового джерела.
- Тестові файли посилаються на C:, тому xls і xlsb з них обробляйте з тимчасовою папкою на іншому диску: `local … --temp D:\Temp\spo`.
